# Architecture Notes

## Product Shape

The platform follows a tenant hierarchy:

- `SUPER_ADMIN` manages KAO, client, and company tenants.
- `KAO` manages clients and their companies.
- `CLIENT` manages companies.
- `COMPANY` owns compliance records, uploads, approvals, notifications, audit trail, branches, and master data.

## Backend Modules

- `auth`: login, password reset, token identity.
- `super-admin`, `kao`, `client`, `company`: role-specific tenant workflows.
- `compliance`: upload analysis, Compliance Master, KPIs, analytics, bulk import.
- `approval`: submit, approve, and reject Compliance Master records.
- `notifications`: company notifications and read state.
- `audit`: enterprise activity logs.
- `master`: configurable master data and holiday calendars.

## Enterprise Controls

- Approval status is stored on `ComplianceMaster` as `DRAFT`, `PENDING_APPROVAL`, `APPROVED`, or `REJECTED`.
- Notifications are company-scoped and generated for key workflow events.
- Audit logs capture actor, action, entity, company scope, changes, reason, IP, user agent, and status.
- Request IDs are assigned to each API request and included in structured logs.
- Compliance due-date, expiry-date, and overdue notifications are generated by a lightweight scheduled worker.
- Upload metadata flows through a storage service so local disk can be replaced by S3 or Azure Blob later without changing business controllers.

## Implemented Startup Architecture Steps

- Repeated Compliance Master mapping is centralized in `complianceMaster.service.js`.
- Zod validation is active on Compliance Master create/bulk endpoints and approval actions.
- A scheduled worker creates due-date, expiry-date, and overdue notifications.
- Local file metadata is behind `storage.service.js`, with a production path for S3/Azure Blob adapters.
- Request IDs and structured logging are implemented with `pino`.

## Future Production Hardening

- Add S3 or Azure Blob upload/download adapters inside the storage service.
- Add a queue-backed scheduler such as BullMQ when notification volume grows.
- Expand Zod validation to every auth, tenant, master data, and profile endpoint.
- Send structured logs to CloudWatch, Azure Monitor, Datadog, ELK, or Grafana Loki.
